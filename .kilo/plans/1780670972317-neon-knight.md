# Plan de Refactoring - Módulo de Comunicación USART

## Análisis del Problema Actual

### Archivos Involucrados
- `Core/Src/usart.c` - Driver CubeMX con código de aplicación mezclado
- `Core/Src/hardware/usart_hw.c` - Capa de abstracción con acceso a detalles internos
- `Core/Src/tasks/task_comm.c` - Tarea de comunicación
- `Core/Src/stm32f3xx_it.c` - Manejo de interrupciones
- `Core/Inc/usart.h` - Header del driver
- `Core/Inc/hardware/usart_hw.h` - Header de abstracción

### Problemas Identificados

1. **usart.c contiene código de capas superiores:**
   - Buffers de datos (`dma_uart_tx_buffer`, `dma_uart_rx_buffer`, `sdin_buffer`)
   - Variable de estado `TxbufferHandler` (implementación de buffer circular duplicada)
   - Funciones de aplicación: `sendChar`, `TransmitionStart`, `receptionStart`, `uartOnReceive`
   - Función `comm_task()` que es una tarea del sistema
   - Callbacks `HAL_UART_TxCpltCallback`, `HAL_UART_RxCpltCallback`

2. **Duplicación de buffers:**
   - usart.c define su propio buffer con `cBufferHandler_t`
   - usart_hw.c define `rx_circular_buffer` con `circular_buffer_t` diferente

3. **task_comm.c mezcla abstracciones:**
   - Incluye tanto `usart.h` como `usart_hw.h`
   - Llama a `comm_task()` del driver

4. **Callbacks en usart.c:**
   - `HAL_UART_TxCpltCallback` tiene lógica de buffer que debería estar en abstracción
   - `HAL_UART_RxCpltCallback` llama a `uartOnReceive()` en lugar de exponer evento

## Pasos de Implementación

### PASO 1: Limpiar usart.c - Mantener solo código de CubeMX

**Quitar de usart.c:**
- Buffers `dma_uart_tx_buffer`, `dma_uart_rx_buffer`, `sdin_buffer`
- Variable `TxbufferHandler` y tipo `cBufferHandler_t` (ya existe en circular_buffer.h)
- Funciones: `sendChar`, `TransmitionStart`, `receptionStart`, `uartOnReceive`
- Función `comm_task()`
- Callbacks: `HAL_UART_TxCpltCallback`, `HAL_UART_RxCpltCallback`
- Tipos `bufferType_t`, `TaskState_t`

**Mantener en usart.c:**
- `huart2`, `hdma_usart2_rx`, `hdma_usart2_tx` (externados en header)
- `MX_USART2_UART_Init()`
- `HAL_UART_MspInit()` / `HAL_UART_MspDeInit()`

### PASO 2: Actualizar usart.h

**Mantener:**
- Declaraciones de handles: `huart2`, `hdma_usart2_rx`, `hdma_usart2_tx`
- `MX_USART2_UART_Init()`

**Quitar:**
- Todo lo relacionado con buffers y estados propios
- Prototypes de funciones que pasan a usart_hw

### PASO 3: Refactorizar usart_hw.c - Capa de abstracción completa

**Agregar a usart_hw.c:**
- Buffer circular único para TX (reemplazar cBufferHandler_t)
- Buffer de recepción (mantener `rx_circular_buffer`)
- Funciones de transmisión con gestión DMA
- Callbacks que serán llamados desde usart.c

**API pública usart_hw.h:**
```c
void usart_hw_init(void);
void usart_hw_start_rx(void);
void usart_hw_idle_handler(void);  // Llamado desde ISR
void usart_hw_send_str(const char *str);
void usart_hw_send_buf(uint8_t *data, size_t len);
```

**Agregar funciones internas para callbacks:**
```c
// Llamadas desde usart.c callbacks
void usart_hw_on_tx_complete(void);
void usart_hw_on_rx_complete(void);
```

### PASO 4: Modificar stm32f3xx_it.c

Actualizar para que los callbacks de UART llamen a la capa de abstracción:
- `HAL_UART_TxCpltCallback` → `usart_hw_on_tx_complete()`
- `HAL_UART_RxCpltCallback` → `usart_hw_on_rx_complete()`

### PASO 5: Actualizar task_comm.c

- Incluir solo `usart_hw.h` (no `usart.h`)
- Quitar llamada a `comm_task()` (la lógica integrarla en usart_hw)

### PASO 6: Verificar integración

- Asegurar que main.c inicializa correctamente
- Verificar que compilationFlags y configuración no rompan
